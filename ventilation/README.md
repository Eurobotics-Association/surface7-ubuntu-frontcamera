# Surface Pro 7 ventilation check

**Read-only snapshot: 2026-10-05.** No packages, settings, fan controls, firmware, or kernel state were changed.

## Findings

- DMI identifies Surface Pro 7 (model 1866), Intel Core i7-1065G7, Surface UEFI 24.109.140 (2025-07-21); the Surface Serial Hub log reports SAM firmware 14.800.139. Ubuntu is 24.04.5 LTS. The i7 configuration is the fan-equipped SP7 variant.
- The user heard the fan start during a workload when their thermal watcher reported CPU temperature just over 85°C. A follow-up sample, taken after that event, showed CPU package 53°C and cores 53–57°C. This confirms the fan spins; it does not provide RPM or establish an exact repeatable threshold. The user's recurring desktop thermal warning is generated by their own watcher, not by Ubuntu or the kernel.
- CPU temperature sensing works. The ACPI/DPTF readings were about 35–52°C in the earlier sample; several generic ACPI zones logged “No valid trip points.” Surface/DPTF zones `SEN1–SEN9` and `B0D4` are also present. `B0D4` exposes firmware “active” trips at 80, 85, 90, and 95°C, plus hot/critical trips at 102/104°C. The observed fan start near 85°C is consistent with one of those trip values, but the zone has no cooling-device binding, so the match is unproven.
- Linux exposes no fan RPM sensor, no `Fan` cooling device, and no thermal-zone-to-cooling-device bindings. Processor, power-clamp, TCC-offset, and PCIe cooling devices are present. Upstream's read-only `surface_fan` hwmon driver documents RPM reporting for Surface Pro 9 only, not SP7. Adding SP7 reporting would first require confirming that its SAM firmware exposes a compatible fan query and kernel support.
- `thermald` 2.5.6 and `power-profiles-daemon` 0.21 are installed and their current-boot journal says both started. The Surface platform profile is `balanced`. No `/etc/thermald/thermal-conf.xml` exists; thermald separately logs “sensor id 24: No temp sysfs for reading raw temp.” That daemon message concerns its sensor mapping, not the user's watcher alert or CPU temperature reading.
- Microsoft publishes no numeric SP7 fan-start temperature. Its guidance says fan speed depends on workload, charging, ambient temperature, and power mode; higher-performance modes allow faster fan operation. Microsoft's latest SP7 history lists UEFI 24.109.140.0 (September 2025), matching this device; that release is described as a security fix, not a fan fix. Intel lists 100°C Tjunction for this CPU.

## Assessment and safe next steps

The fan is working at least intermittently; the reported start above 85°C makes a permanently failed fan unlikely. Linux still provides no direct fan telemetry. The clearest software-side lead is the current `balanced` profile: Linux Surface guidance says it prevents fan ramping for quieter operation. A Linux Surface report from an SP7 i7 describes temperatures approaching 90°C and severe throttling; the older widely cited SP7 throttling report concerns the fanless i5 and should not be treated as proof about this i7.

First, record the watcher temperature when the fan starts and stops during normal use, without adding a stress test. If you want airflow earlier, a supervised comparison of the built-in balanced and balanced-performance profiles is the least invasive software experiment; it is reversible, can raise CPU heat, and should be done while monitoring temperature below the 95°C operating limit. Thermald can limit CPU heat through processor/power controls, but cannot set an unexposed fan curve. No profile or thermal setting has been changed.
